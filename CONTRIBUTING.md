# Contributing to Living World

Thank you for considering contributing. Living World welcomes people at all experience levels. A useful question, a careful test, a clear bug report or a small documentation improvement can be just as valuable as a large code change.

## Before you start

- Read the README, [project overview](docs/PROJECT_OVERVIEW.md), [roadmap](ROADMAP.md) and [licensing policy](LICENSING.md).
- Check existing issues and discussions to avoid duplicate work.
- For a substantial feature, open an issue or discussion first and agree the scope before starting.
- If you are new, say so. We can help break work into manageable tasks.
- Do not access or submit private workstream material unless the project lead has explicitly invited you.

## Ways to contribute

Code, research, design, NPC behaviour, worldbuilding, art, testing, documentation, accessibility and constructive feedback are all welcome. Experience is not a requirement.

## Issues and tasks

Use GitHub Issues for public tasks. Suggested labels include:
- `good first issue` — a small, well-scoped starting task;
- `help wanted` — contributions welcome;
- `beginner friendly` — suitable with guidance;
- `documentation`, `research`, `design`, `art`, `code`, `testing`;
- `bug`, `performance`, `question`, `discussion needed`.

When opening an issue, include the goal, context, reproduction steps for bugs, expected result and relevant evidence. Remove secrets and personal information before posting.

## Pull request workflow

1. Fork the repository and create a focused branch from `main`.
2. Make one logical change per pull request where practical.
3. Explain why the change is needed, what changed and how it was tested.
4. Link the related issue.
5. Include screenshots or test notes when useful.
6. Respond constructively to review feedback.

The Founder and Creative Director is the final project decision-maker and release gatekeeper. A pull request is not accepted until explicitly approved and merged by an authorised maintainer.

## Unreal Engine and asset guidance

- State the exact Unreal Engine version used. The current target is UE 5.8.
- Do not commit generated folders such as `Binaries/`, `Intermediate/`, `Saved/` or `DerivedDataCache/`.
- Discuss large binary files before adding them; Git LFS or Perforce may be more appropriate.
- Do not submit purchased assets, licensed datasets or files copied from tutorials unless redistribution is expressly permitted.
- Document plugins, dependencies, versions, data sources and applicable licences.

## External data and security

For each data source, record its provider, URL, access date, coverage, licence, attribution requirements, redistribution permissions, update frequency and rate limits.

Never commit API keys, credentials, personal data or confidential material. Keep privileged credentials off distributed game clients. Distinguish real observations, forecasts, fictional simulation values and developer overrides.

## Contribution rights and permissions — important

Living World currently uses a **restricted / all-rights-reserved** publishing policy. Public visibility does not grant the public a licence to reuse project materials.

You retain rights in original work you contribute unless a separate written agreement says otherwise. A contribution is not automatically accepted for inclusion, and submitting a pull request does not by itself transfer copyright or grant a public reuse licence.

Before a substantial contribution is incorporated into a release, the project will agree in writing the permissions needed for Living World to use, modify, maintain and distribute that contribution. Do not submit work you do not own or are not authorised to contribute. Identify third-party material and its terms.

No payment, revenue share, employment or ownership is promised unless agreed separately in writing.

## Community conduct

Be welcoming, patient and constructive. Harassment, discrimination, personal attacks, intimidation, doxxing and deliberate disruption are not acceptable. See [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md).

## Need help?

Open a GitHub Discussion or an issue with the question label. Explain what you are trying to do, what you have tried and where you got stuck. Beginners are welcome.
